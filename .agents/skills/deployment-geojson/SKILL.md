# deployment-geojson

部隊配置図の部隊を、地図の画素から経緯度の点にする。部隊の読み取りは `unit-symbols`、基準点の作成は `deployment-batch` が行い、このスキルはその結果をつないで、GeoJSON にする。

## 使い方

```sh
uvx --with numpy --with opencv-python-headless --with pypdfium2 --with pillow --with scikit-image \
  python scripts/deployment_geojson.py --results work/results.jsonl --runs work/runs --src pdfs --out geojson
```

- 地図 1 枚につき 1 ファイルを、`<ミッション>_<日付>_<PDF のハッシュ 12 桁>.geojson` の名前で書く。ファイル名に参照番号は入らない。
- `summary.jsonl` に、地図ごとの部隊数、位置が付いた数、付かなかった理由の内訳を書く。
- 同じ PDF (同じハッシュ) が 2 つあるときは、1 つだけ書く。
- 道具のコミットは、リポジトリの HEAD である。道具のファイルが未コミットか変更中なら、書き出しを止める。コミットを渡したいときは `--tool-commit` を使う。

## どの点を使うか

地図の本体と、枠で描かれた拡大図を、それぞれ別のパネルとして扱う。部隊の位置を含む最も小さい (細かい) パネルを使う。1 つの候補に答えが複数あるとき (地名の答えと、`graticule-gcps` の `grid_` の答え) は、関門を全て通った答えを先に採る。

- 関門を全て通った地図のパネル: そこにある部隊のうち、基準点の凸包から、基準点の広がり (大きい側) の 0.30 を超えて外にあるものを除く全て (`GLOBAL_HULL_MARGIN`)。
- 点の広がりの関門だけで落ちたパネル (部隊の枠が拡大図の空きを取る、町が地図の一部にしかない): 部隊の点が、基準点を結んだ範囲 (凸包) の内側にあり、基準点を 1 つずつ抜いたときの点の動きが 3 px 以下のときだけ使う。画像全体の答えとしては、使わない。
- それ以外の関門で落ちたパネル: 使わない。

凸包には 3 px の余裕を持たせる。基準点にした町に部隊がいるとき、部隊の点は町の印の上にあり、同じ町で読んだ基準点と 1〜2 px ずれる。MONUSCO の 2025 年の拡大図は、基準点の町が 1 本の道に沿って並ぶので、この町の部隊 22 部隊が凸包の外 (0.2〜1.9 px) に出ていた。

基準点を抜く確かめだけでは足りなかった。基準点が全て地図の西側にある MINUSMA の図では、北東の部隊が 13〜18 km ずれていたのに、点の動きは 1.2 px だった。当てはめが基準点の外で曲がることを、この確かめは見ない。そのため、凸包の内側にあることも求める。

関門を全て通った地図でも、基準点から遠い部隊は外挿である。地図の隅 (表、凡例、拡大図の領域) の積みは、隠れた主図の町の名前を横に持ち、主図の変換で大西洋に落ちた (MONUSCO の 2016 年 8 月、Rwindi と Panzi の積みが経度 10〜12、南緯 12 度)。余白 0.30 は、2000 年から 2016 年の 562 地図で決めた。0.10〜0.30 にある積みは実在の町 (Robertsport、Plibo、Harper、Rutbah、Libreville) の上にあり、0.34 以上は町から 150 km 以上離れていた。目で見た標本で、評価ではない。2024 年と 2025 年の MINUSCA では、東の端の町 (Obo、Zemio) の 9 点が、余白の外になった。

使われなかった部隊は、理由別に数えて `summary.jsonl` に残す。

- `no_location`: 部隊の積みに位置が付かなかった
- `outside_panels`: どのパネルにも入らない
- `outside_hull`: 局所のパネルで、基準点の範囲の外 (3 px を超える)。関門を通ったパネルで、凸包から広がりの 0.30 を超えて外
- `uncertain`: 局所のパネルで、点の動きが 3 px を超えた

## 公開の前の確かめ (海と町)

関門は、基準点どうしが合っていることしか確かめない。公開の前に、関門とは別に次の 2 つを、この順に流す。どちらも、渡したファイルは書き換えず、`--out` に書く。

```sh
python scripts/sea_check.py --src geojson --out geojson-sea --cache sea-cache.json
python scripts/town_check.py --results work/results.jsonl --runs work/runs --src pdfs --geojson geojson-sea --out geojson-checked
```

- `sea_check.py`: 点と、その上下左右 0.05 度の 4 点のどれにも陸が無ければ、海の点として捨てる。陸かどうかは、自前の Nominatim の逆ジオコーディング (zoom 5) で調べる。サーバーは Python の既定の User-Agent を拒む (403)。UNOCI の 2006 年の図は、ギニア湾の沖 100 km に部隊を置いていた。
- `town_check.py`: 地図の町の印を、その地図のモデルで経緯度にし、そばの名前で Nominatim が返す町と比べる。距離の中央値が 10 km 以下で、測れた町が 3 つ以上の地図だけを書く。全ての地図の測定は `town_check.jsonl` に残る。主図の対角線の地上の長さ (`extent_km`) も残す。
  - 名前と印の組は、name-gcps と同じ決め方にする。名前は、より長い句に含まれない語か句 (「Kafr Shams」の「Kafr」だけを引かない)。印は、名前の箱の外にあり、箱から名前の高さの 1.2 倍以内のもの (箱の中の丸は文字の一部)。1 つの印は、一番近い名前 1 つだけの町にする (別の形の印で描かれた首都が、隣の町の輪を取らない)。
  - 町は、部隊と同じ規則 (`deployment_geojson.place`) で選んだパネルのモデルで写す。その点を含む一番小さいパネルで、点ごとにしか使えないパネルは基準点の近くでだけ。拡大図の中の町を主図のモデルで写すと、1,000 km 離れる (MONUSCO の 2025 年)。
  - 最大値ではなく、中央値を見る。同じ名前の別の町や、表の中の名前は、数十 km から数千 km 離れる。
  - 10 km は、2004〜2019 年の地図の分布の空白 (9.8〜13.4 km) を見て決めた (2026-11-09)。ただし、そのときの組の決め方には上の 3 つの誤りがあった。直した後 (2026-11-10) の分布には、km の空白が無い。国全体を描いた小さい縮尺の地図 (コンゴ、スーダン) が 8〜17 km に続く。
  - 主図の対角線に対する割合で見ると、278 地図のうち 274 地図が 0.68% 以下で、残る 4 地図 (MONUSCO の 2019 年、1.04〜1.29%、41〜51 km) との間に空白がある。しきい値を割合に変えるかは、まだ決めていない。

どの確かめを通したかは、各ファイルの `checks` に残る。

| 欄 | 書く道具 | 中身 |
|---|---|---|
| `checks.hull_margin` | `deployment_geojson.py` | 関門を通った図に当てた余白 (0.30) |
| `checks.sea` | `sea_check.py` | 升目の大きさ (度) と、捨てた点の数 |
| `checks.town` | `town_check.py` | 測れた町の数、中央値 (km)、しきい値、通ったか |

`checks` が無いファイルは、この記録を始める前 (2026-11-09 より前) に作ったものである。確かめていないとは限らないが、ファイルからは分からない。

## 出力

FeatureCollection の最上位に、`based_on` ("Based on United Nations map")、`disclaimer` (無保証、間違いの可能性、国連の製品でないこと)、`mission`、`map_date`、`source_sha256`、`tool`、`tool_commit`、`checks` を持つ。`tool_commit` は道具の入ったコミットで、道具のファイルが変更されたままなら止まる。git の外の写し (コンテナの中の作業場所など) では、道具のファイルのハッシュを `unversioned-sha256:<16 進>` として入れる。各点には次が入る。

| 欄 | 意味 |
|---|---|
| `label`、`inner` | 枠の右の文字、枠の中の略語 |
| `symbol`、`arm`、`echelon`、`size_marks` | 記号の形、兵科、規模、規模の印 |
| `nearest_text` | 点のそばの一番近い単語。地名とは限らない |
| `located_by` | `leader` (線の先) か `adjacent` (印が隣) |
| `panel_local`、`map_ok`、`std_px` | 局所のパネルか、地図全体が関門を通ったか、点の動き (px) |
| `no_warranty` | 点を 1 つだけ取り出されても無保証が残る短い文 |

日付 (`date`、`map_date`) は PDF の作成日で、地図が表す時点とは限らない。

## 公開してよい形

国連の地図から作った派生物として、"Based on United Nations map" と書く。地図の参照番号は入れない。時期は入れてよい。元の PDF の SHA-256 と、道具のコミットを入れる。正確さは一切保証しない。

- 属性から、ファイル名の語 (`map`) と題名 (`title`) を除く。どちらにも参照番号が入る。
- 書き出しの前に、ファイル名と題名から 4〜5 桁の数字を参照番号として集め、出力の全文を探す。1 つでも残っていれば、書き出しを止める。
- 国連の名称そのもの (United Nations) は、`based_on` と `disclaimer` の中で出典として書く。略称 (MONUSCO など) は残す。

## 限界

- 部隊の位置は、地図の場所の印に、線の先が一致した分だけである。印と実際の地物の違い、地図の作図上のずれは、そのまま入る。
- `nearest_text` は一番近い単語を拾うだけなので、別の町の名前が付くことがある。
- 点の広がりだけで落ちた地図の点は、地図全体の答えとしては関門を通っていない。`map_ok` が false のものとして、分けて扱う。
