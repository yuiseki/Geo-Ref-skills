# deployment-batch

国連の平和維持活動の配置図は、ミッションごとに何十もの版がある。版ごとに手で合わせるのは現実的でない。このスキルは、1 つのディレクトリの PDF を、新しい日付から順に、1 件 1 行の結果にしていく。

## 使い方

```sh
uvx --with pypdfium2 python scripts/batch.py --src pdfs --out work --min-year 2017
```

- `--missions missions.json`: ファイル名から略称への対応 (JSON)。PDF の題名とファイル名から略称が読めないときに渡す。ファイル名に地図の参照番号が入るので、これは公開物に入れない入力として扱う。
- `--only a.pdf b.pdf`: 指定した PDF だけ。`--limit N`: 未処理の N 件だけ。
- 同じ `--out` で再実行すると、結果のある PDF は飛ばして続きから進む。

## 1 件でやること

1. 地図の候補を作る (地図の本体と、枠で描かれた拡大図)。
2. 順位の上位 3 つと、上位 8 つのうちの全ての枠について、PDF の文字の層から (なければ OCR で) 地名を取り、地名検索で基準点を作る。アフィン、次に射影の順に試す。
3. 地名で関門を通らず、候補が PDF から切り出したものなら、枠の経緯度の目盛りで基準点を作り (`graticule-gcps`)、同じくアフィン、射影の順に試す。UNDOF のゴラン高原の図は、町が地名検索で十分に当たらないが、枠の四辺に 5 分ごとの目盛りがある。
4. 関門を通った最初の候補と手法で止める。宣言された失敗 (地名が合わなかった) は、手法を替えても変わらないので次の手法を試さない。

関門を通ったら、その地図の他のパネル (順位の上位 4 つと、枠の全て) も同じ手順で試し、それぞれ単独で通ったものを残す。拡大図の中の部隊は、拡大図自身の基準点で位置を決めるためである (MONUSCO の 2023〜2024 年版では、部隊の 4 分の 3 が拡大図の中にある)。

どの関門も緩めない。関門を通らなかった答えも、`gates.c<候補>.<手法>.json` と `answer.c<候補>.<手法>.json` として残る。目盛りの答えは `answer.c<候補>.grid_<手法>.json` と `gates.c<候補>.grid_<手法>.json` に分ける。同じ名前にしていたら、目盛りの失敗の宣言が地名の答えを上書きし、関門の結果だけが残った (MONUSCO 2025 年 9 月)。点の広がりの関門だけで落ちた答えは、後段で局所的に使える。

## 結果

`work/results.jsonl` に PDF ごとの 1 行が入る。

| stage | 意味 |
|---|---|
| `ok` | 関門を全て通った。`cand`、`method`、`gcps`、`loo`、基準点の出どころ `gcps_from` (`name-gcps` か `graticule-gcps`) が入る |
| `failed` | どの候補も通らなかった。`tried` に候補、手法、落ちた関門が入る |
| `candidates` | 地図の候補が 1 つも取れなかった (文字の層がなく、描かれた地図もない PDF など) |
| `error` | 例外。理由が入る |

## ミッションの表

`MISSIONS` は、ミッションの略称から、その地図に出る国の国コードへの対応である。部隊の派遣国名 (BANGLADESH など) が地名として当たらないように、地名検索をこの国々に絞る。表にない略称の地図は絞らずに試す。略称は、題名、ファイル名の順で、単語全体として探す。

`UTM_ZONES` は、UTM の方眼で描かれ、帯の番号を書いていない図の、ミッションごとの帯である (UNIFIL は 36N)。`graticule-gcps` に渡す。

## 資源の上限

実データを読む工程は、1 つずつ、メモリ 8 GB、スワップなし、CPU 400% の枠の中で動く。1 件の PDF が上限を超えて落ちても、全体は止まらず、その PDF が `failed` か `error` になる。1 つの工程の時間の上限 (30 分) も、枠そのもの (`RuntimeMaxSec`) に掛ける。Python の `subprocess` の時間切れは systemd-run の 1 プロセスしか止めず、枠の中の name-gcps と tesseract が 29 時間動き続けていた (2026-11-06)。systemd の `systemd-run --user --scope` が使える環境が前提である。

## 後段

関門を通った地図 (と、点の広がりだけで落ちた地図の一部) から、部隊の位置の GeoJSON を作るのは、`deployment-geojson` の役目である。
