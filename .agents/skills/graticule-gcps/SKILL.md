# graticule-gcps

地図の中には、地名検索で位置の分かる町が少ないのに、枠の四辺に経緯度の目盛りを印刷しているものがある。UNDOF のゴラン高原の図 (2025 年) は、5 分ごとに、短い線と 35°50'E のような文字を枠の四辺に置いている。地名で合わせると、関門を通る基準点が 7 つしか集まらなかった (12 必要)。目盛りは PDF の文字と線の層にあり、画像として読む必要がない。

## 使い方

```sh
uvx --with pypdfium2 python scripts/graticule_gcps.py map.pdf --dpi 150 --box-px x0 y0 x1 y1 --out answer.json [--method affine]
```

`--box-px` は、`--dpi` で描いたページから切り出した候補の範囲である (document-maps の候補の `from.box_px`)。基準点は、その切り出しの画素で返る。`deployment-batch` は、地名で合わなかった候補に、これを自動で試す。

## 手順

1. 文字: 文字の層を、空白と改行で区切った並びとして読み、度、分、秒、半球の形 (`36°20'E`、`32°45'N`、`8°35'S`) に合うものを目盛りの文字とする。UNDOF の左右の辺の文字は、1 字ずつ縦に並べて書かれている。文字の層は書いた順に返すので、位置から語を組まずに、並びのまま読む。
2. 線: 文字ごとに、そばにある 6 pt 以下の真っすぐな線のうち、辺に沿った位置が文字の中央と 1.5 pt 以内で一致するものを、その文字の目盛りとする (経度は縦の線、緯度は横の線)。UNDOF では、目盛りの線と文字の中央は 0.2 pt 以内で一致した。線がない文字は使わない。
3. 経線と緯線: 同じ値の目盛りが 2 つの辺にあれば、その 2 点を結ぶ。UNDOF の図は北が真北でなく、36°10'E の目盛りは上の辺で x = 428 pt、下の辺で 434 pt にある。1 つの辺にしかない値 (左上の地球儀の絵で上の辺の文字が隠れた 35°40'E と 35°45'E) は、2 点で引けた同じ軸の線の平均の向きで引く。
4. 基準点: 経線と緯線の交点を、切り出しの範囲の内側だけ基準点にする。

線を直線とみなすのは、地図の投影でほぼ直線である範囲に限る。UNDOF の図の 70 km では、横メルカトル図法の緯線の曲がりは 50 m に満たず、150 dpi で 1 画素より小さい。

## 確かめ

UNDOF の 2025 年 9 月の図で、35 の文字の全てに目盛りの線が見つかり、74 の基準点ができた。関門は、アフィンで全て通った (1 点を抜いたときの残差は最大 2.46 px、射影では 1.28 px)。基準点は地図自身の目盛りなので、関門とは別に、地名検索 (自前の Nominatim) で位置の分かる町の印と比べた。Al Asbah、Kafr Shams、Aş Şanamayn、Nawá、Jabā、Ḩaḑar の 6 つが 30〜130 m で一致した。

## 限界

- ベクタ PDF の文字と線の層だけを読む。スキャンした地図は読めない。
- 目盛りの文字が度と半球の記号を持たない地図 (`35°50'` だけ、または `35.5`) は読まない。
- 地図の中に引かれた経緯線 (目盛りでなく線) を、端から端までたどることはしない。
- 方眼が別の座標系 (UNDOF の Palestine Belt Grid の 10 km 方眼) のときは、その数字は読まない。経緯度の目盛りだけを使う。
