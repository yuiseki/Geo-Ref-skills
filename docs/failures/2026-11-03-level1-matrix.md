- 課題: `evals/matrices/level1.json`。osm-liberty の z15、900 x 700 画素。場所は東京の都心、札幌の碁盤の目、十勝の畑の 3 つ。歪みは similarity、affine、projective の 3 種、強さは 0.25、0.5、1.0、種は 2 つ。合わせて 54 課題。
- 解き方: 道具だけ (エージェント無し)。手がかりの枠で参照を取る、feature-registration (SIFT、比 0.75、MAGSAC 3 画素、整合する対応 20 以上)、georef-gates (既定の閾値)、採点。
- 正確の線: 画像の半径に対する最大誤差 1% 以下。
- コマンド: `python3 -u evals/scripts/run_matrix.py evals/matrices/level1.json --work tmp/matrix/level1 --out tmp/matrix/level1.tsv`

## 失敗 1: 関門が厳しすぎる (over_strict、4 件)

- 該当: 東京の affine と projective の強さ 1.0 の種 2、札幌の affine と projective の強さ 1.0 の種 2。
- 落ちた関門: `loo_residual`。最大の leave-one-out の残差が 3.07〜3.39 画素で、閾値 3 画素を少し超えた。最大誤差は 0.55〜1.57 m で正確だった。
- 崩れた前提: 最大の残差を見る関門は、GCP が十数点のときを想定している (Bahgat と Runfola 2021 の地名の GCP)。特徴の対応では GCP が 100〜400 点あり、位置の雑音の分布の端だけで最大が閾値を超える。点の数が増えるほど、最大は大きくなる。
- 直し方の案 (未実施): 閾値を緩めるのでなく、外れた GCP を 1 点ずつ除く道具を足し (Bahgat と Runfola 2021 の手順)、除いた割合を新しい関門にする。除く割合に上限が無いと、関門が素通りになるため。

## 失敗 2: 対応が足りない (refused、4 件)

- 該当: 十勝の affine と projective の強さ 1.0 の種 1、2。
- 道具の出力: 比の検定を通った対応が 11〜32、MAGSAC で整合したものが 8〜11 (閾値 20)。
- 歪みの例 (種 1): 縮尺 1.31、縦横比 1.20、せん断 -0.14。
- 対照: 同じ十勝の similarity の強さ 1.0 (回転と一様な縮尺) は、2 件とも解けた (GCP 42、47 点)。
- 崩れた前提 (仮説): SIFT の記述子は回転と一様な縮尺には不変だが、アフィン (縦横比、せん断) には不変でない。地物のまばらな地図では、その差で対応が閾値を割る。
- 確かめ方の案 (未実施): 同じ課題で、課題の画像に傾きを模した複数のアフィン変換を掛けてから照合する (ASIFT)。解けるようになれば、仮説を支持する。
- 失敗の宣言は正しい振る舞い。推測の答えは出ていない。
