# レベル 5: 文書の中の地図、最初の評価 (2026-11-04)

## 条件

- 課題: `evals/matrices/level5-docs.json`。osm-liberty (文字あり) の 900x700 の地図。静岡、仙台、メルボルン、シアトル、ズーム 15 と 16、相似と透視の歪み、強さ 0.5 と 1.0、種 40。16 枚の地図を、それぞれ 2 種類の文書に入れた 32 課題 x 2 = 64 課題。
- 文書は `make_doc_task.py` の plain の配置 (A4、本文と棒グラフの間に地図)。embedded は地図を 1 つの画像として埋め込んだ PDF、scan はページ全体を 150 dpi の 1 枚の画像にした PDF。
- 道具に渡すのは PDF と国だけ。候補を順に切り出し、レベル 4 と同じ道 (place-hint、feature-registration、関門) に通す。道具が失敗を宣言したときだけ次の候補へ進む。
- 流したのはコミット a212041 の道具。候補の並べ方を `map_candidates.py` の 1 つの順位にまとめる前の版で、embedded は埋め込み画像を大きい順、scan はページから切り出した矩形を並べていた。

## 結果

| 結果 | embedded | scan | 計 |
|---|---:|---:|---:|
| ok | 14 | 13 | 27 |
| over_strict | 1 | 1 | 2 |
| refused | 17 | 18 | 35 |
| gate_hole | 0 | 0 | 0 |

- 場所ごと: 仙台 ok 14 / refused 2、静岡 ok 4 / refused 12、メルボルン ok 4 / over_strict 2 / refused 10、シアトル ok 5 / refused 11。
- ok の誤差の最大は、embedded が 0.08〜1.64 m、scan が 0.64〜2.39 m (画像の半径の 0.06〜0.10%)。
- 地図を見つける段は外れていない。embedded で解けた課題は全て 2 番目の候補 (900x700 の地図の画像そのもの) で、1 番目のページ全体の画像は毎回 place-hint で止まった。scan で解けた課題は全て 1 番目の候補 (ページから切り出した矩形) だった。

## 止まった理由

- 35 件のうち 34 件は place-hint の段。scan の 17 件は読めた地名が 0 件だった。scan では地図が 150 dpi で描かれ、元の 900 px より小さくなることが多く、文字が OCR に読めない大きさになる。
- embedded の拒否は、そろった地名の重みや数が閾値に届かないもの。重み 1.48、1.50 のように境目のものもある。これはレベル 4 の同じ地図でも起きる止まり方で、文書から取り出したことによるものではない。
- 関門が大外れを止めた例が 1 件ある。メルボルン z16 透視 0.5 の scan は誤差 1.4e5 m の答えを出したが、spread、loo_residual、edge_uncertainty、geometry、inside_hint の各関門が拒否した。

## 関門が正しい答えを落とした 2 件

メルボルン z15 透視 1.0 の embedded (誤差 0.55 m) と scan (誤差 2.88 m)。どちらも inside_hint の関門だけで落ちた。place-hint の求めた枠と、答えの位置がずれていたことになる。直すなら place-hint の枠の大きさの側で、関門を緩めることはしない。

## 次に試すこと

- scan の文字が読めない件: ページを描く dpi を候補の大きさに合わせて上げる (地図の切り出しは 150 dpi で見つけ、OCR には 300 dpi で切り出し直す)。
- この評価のあとで、候補の並べ方は `map_candidates.py` の 1 つの順位に変えた。同じ 64 課題を新しい版で流し直し、比べる。
