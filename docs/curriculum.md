# レベル 1〜5: 模擬の課題で道具と関門を育てる

真の変換が分かる課題を tile.yuiseki.net のタイルから作り、道具と関門とスキルを採点する。正解は課題を作ったときの変換そのものなので、誤差を厳密に測れる。

## 共通の作り方

1. 場所 (経緯度の範囲) とズームを決め、タイルをつないで、正しい位置の画像 (Web メルカトル、EPSG:3857) を作る。
2. その画像に、既知の歪み T を掛けて、課題の画像を作る。
3. エージェントには、課題の画像と、レベルごとに決めた手がかりだけを渡す。T と、正しい位置の画像は渡さない。
4. エージェントは、課題の画像の画素から地上の座標への変換 (GCP の集合と、当てた変換) を返す。
5. 採点は、課題の画像の全体に格子の点を置き、エージェントの変換で写した位置と、T の逆で写した真の位置の差で行う。誤差は 2 つ出す。
   - 地上の距離 (m)。最大値と中央値。
   - 画像の半径に対する割合 (%)。Bahgat と Runfola (2021) の指標にそろえる。

## 典型的な歪み

1 つずつ、次に組み合わせて掛ける。どの歪みにも、強さの段階を付ける。

| 歪み | 何を模すか |
|---|---|
| 平行移動、回転、一様な拡大縮小 | スキャンの置き方 |
| アフィン (縦横で違う縮尺、せん断) | スキャナの送りのむら、紙の伸縮 |
| 射影 (ホモグラフィ) | 斜めから撮った写真 |
| 滑らかな非線形 (TPS、多項式) | 紙のよれ、折り目 |
| 投影の違い (正距円筒、UTM、ランベルト正角円錐) | 地図そのものが Web メルカトルでない |
| 切り取り、余白、周りの枠 | 図郭の外の凡例や余白 |
| 色の変化、ぼかし、JPEG の劣化、雑音 | 紙の焼け、スキャンの質 |

## レベル

| レベル | 課題の画像 | 合わせる先 (参照) | 手がかり (案) |
|---|---|---|---|
| 1 | スタイル A のタイルを歪ませたもの | 同じスタイル A | おおよその範囲 (余白付きの経緯度の枠) とズーム |
| 2a | スタイル A のタイルを、灰色または二値 (白黒のコピーを模す) にして歪ませたもの | 同じスタイル A (色付き) | レベル 1 と同じ |
| 2 | スタイル B のタイルを歪ませたもの | 違うスタイル A | レベル 1 と同じ |
| 3 | 要素を絞ったスタイル (文字とアイコンを消したもの、水も文字も無いもの、境界線、川、鉄道だけ) を歪ませたもの | 任意のスタイル X | レベル 1 と同じ |
| 4 | 「これは地図です」とだけ言って渡す任意の画像 | タイル | 無し、または粗い手がかり (国、地名) |
| 5 | PDF や画像の中に地図が含まれるもの。地図の部分だけを切り出してから合わせる | タイル、行政界のベクタ | レベル 4 と同じ、印刷された縮尺 |
| 6 | 位置を合わせた地図の情報 (凡例の範囲など) を、地理空間情報 (GeoJSON) に戻す | レベル 5 の答え | 凡例 |

レベルは、スタイルの名前ではなく、地図に何が描かれているかで決める。e-paper-ez-sign は、配色の違うスタイルとしてレベル 2 に入れていたが、水を背景と同じ白で描き、文字もほぼ無いので、レベル 3 に移した (2026-11-04)。`evals/matrices/level2-epaper.json` の課題の名前が L2 で始まるのは、移す前に流したため。

レベル 3 では、川だけ、鉄道だけの地図より現実に多い、文字とアイコンを消した地図 (osm-liberty-no-text-no-icons を osm-liberty に合わせる) も扱う (2026-11-04、`evals/matrices/level3-notext.json`)。

レベル 2 は、変える変数を 1 つずつにするため、2a (色だけを落とす) を先に置く (2026-11-03)。スタイル B には、osm-liberty と同じ系統の osm-bright から始め、osm-carto へ進む。暗い背景の osm-fiord は、コントラストが低く、色を反転した地図という別の課題を含むので、当面は除く。

レベル 1〜3 では、おおよその範囲 (余白付きの経緯度の枠) とズームを渡す (2026-11-03 に決めた)。手がかり無しで場所を探させると、探索が終わらなくなるおそれがあるため。レベル 4 からは、場所を探すこと自体が課題になる。

### 場所のあたりを付ける道具 (近い将来に足す)

画像の文字を tesseract で読み、自前の Nominatim (https://nominatim.yuiseki.net/ 。公開の nominatim.openstreetmap.org は呼ばない) で地名を引いて、どのあたりの地域かのあたりを付ける。候補が複数出る地名は、地名どうしの配置で絞る (Bahgat と Runfola 2021)。

この方法は、文字ラベルの無い画像 (レベル 3 の川や鉄道だけの図) では使えない。その場合は、手がかりの範囲を渡すか、線の形だけで広い範囲を探す別の道具が要る。

## 各レベルで、道具の側に置く手法の候補

どれも LLM や VLM を使わない、決定論的な処理と古典的な機械学習。

- レベル 1: 局所特徴 (ORB、SIFT、AKAZE) の対応と RANSAC。位相限定相関。
- レベル 2: 色に頼らない表現 (エッジ、勾配の向き、道路や水の領域のマスク) での対応。相互情報量による位置合わせ。
- レベル 3: 線の図形どうしの照合 (距離変換の上での chamfer 照合)。参照の側も同じ要素 (鉄道、川) だけに絞ってから比べる。
- レベル 4: 地名の文字を読み (OCR)、地名辞典の候補の配置を、画像の地名の配置と照合する (Bahgat と Runfola 2021)。図郭の座標注記を読む。
- レベル 6: 凡例の見本との色の距離で範囲を取り出し、文字の縁を落とす。道路を含めるかどうかで答えが変わるので両方を出す ([助言](notes/2026-11-04-pdf-map-advice.md))。
- レベル 5: 地図の枠 (長い直線の矩形、図郭) の検出と切り出し。PDF のベクタの中身を読む。

## 関門 (エージェントが答えを返す前に通る検証器)

正解の無い本番でも使えるものだけを関門にする。正解との差 (上の採点) は関門ではない。

- GCP の数が、変換の自由度に足りているか。
- GCP が一直線に並んでいないか、画像の象限に偏っていないか。
- leave-one-out の残差の最大値が上限の中か。変換の次数は、これで選ぶ。
- 当てた変換が、ありうる範囲か (縮尺の比、せん断、裏返しの有無、経緯度の範囲)。範囲外を丸めない。
- 合わせた後の画像と参照のタイルが、色に頼らない表現で重なるか。

関門が落ちたら、答えを出さずに止め、どの関門で落ちたかを返す。既定の値や合成の点で埋めない。
