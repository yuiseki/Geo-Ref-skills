# 関連する仕事

このリポジトリの道具と関門を設計するために読んだ先行の仕事と、そこから取り入れること、取り入れないことをまとめる。読んだ日は 2026-11-03。数字は各文献に書かれた値で、このリポジトリでは測り直していない。

## uncharted-ta1 (LARA の georeferencing pipeline)

- 所在: https://github.com/DARPA-CRITICALMAAS/uncharted-ta1 (MIT License、Copyright (c) 2025 Uncharted Software Inc.)。読んだ版は commit `7a50dc0` (2025-05-07)。
- DARPA CriticalMAAS の TA1 で、米国の地質図を対象にした georeferencing の実装。ジオリファレンスの部分は `tasks/geo_referencing/` と `pipelines/geo_referencing/`。

### 流れ

1. 地図の領域 (map area) を Detectron2 のセグメンテーションで切り出す。
2. OCR (Google Vision) で文字を取り、図郭の度分秒 (DMS)、UTM、State Plane の座標注記を正規表現で読む。
3. 地域、縮尺、UTM のゾーン、CRS などの metadata を LLM (既定 gpt-4o) に推定させる。地名は Nominatim でジオコーディングする。
4. geofence (地図がありうる経緯度の範囲) を作り、外の座標を落とす。
5. 経度と x 画素、緯度と y 画素の 1 次元の回帰に RANSAC を当てて外れた座標注記を落とす。
6. x → 経度、y → 緯度を、それぞれ (x, y) の多項式回帰で別々に当てる (既定は 1 次)。2 次元の多項式を同時に当てると、点が少ないときに暴れたと書いてある。
7. 検証用の点 (ground truth の画素と経緯度) があれば、測地線距離 (km) の RMSE を出す。

### 取り入れること (決定論的な検査の型)

| 検査 | 実装の場所 | 内容 |
|---|---|---|
| 1 次元の RANSAC | `outlier_filter.py` | 画素と度の関係は単調な直線に近いはず、という仮定で外れた注記を落とす。閾値は度の値の MAD。傾きの符号と、期待する度あたり画素数の 1/5〜5 倍に入るかも見る |
| 傾きの許容 | `outlier_filter.py` | 地図の最大の傾き (角度) から、x 方向の残差の許容を地図の幅で決める |
| 一直線の検出 | `finalize_coordinates.py` | 注記が一直線に並ぶ (短い軸の広がり / 長い軸の広がり < 0.05) と、回帰が悪条件になる |
| 四象限の検査 | `ground_control.py` | GCP が地図の 4 つの象限のそれぞれにあるか |
| geofence | `geo_fencing.py` | 経緯度の範囲で、ありえない座標を落とす。半球 (符号) もここで決める |
| 測地線の RMSE | `georeference.py` | 誤差は経緯度の度ではなく、測地線距離で測る |

### 取り入れないこと (このリポジトリの方針と合わないこと)

このリポジトリでは、失敗は失敗として見えるようにし、作った値を観測として扱わない。uncharted-ta1 には、その逆をする箇所がある。

- 一直線や象限の欠けを見つけると、止めずに、合成の GCP (`DERIVED_KEYPOINT`、四隅の点) を足して回帰を続ける。合成の点は、傾きが小さいという仮定から作った値で、観測ではない。このリポジトリでは、検出したら関門で止め、何が足りないかを返す。
- 変換を作れないとき、geofence の中点を全ての点の答えにする (confidence 0)。座標の値としては正常に見える。このリポジトリでは、答えを出さずに失敗にする。
- 予測した経緯度が ±180、±90 を超えると、黙って範囲に丸める。範囲を超えるのは変換が壊れた証拠なので、丸めずに止める。
- CRS が分からないとき、国と年から決め打ちする (米国とカナダで 1990 年以降は NAD83、1930 年以降は NAD27、それ以外は WGS 84)。日本の旧日本測地系 (Tokyo Datum) と JGD2000/2011 の違いのように、測地系の取り違えは数百 m の誤差になるので、決め打ちせず、根拠 (図の注記) を記録させる。
- 地域や CRS の推定を LLM に任せる。このリポジトリでは LLM や VLM の判断を道具の側に置かない。

## DIGMAPPER (arXiv:2506.16006)

Duan ほか (2025)、"DIGMAPPER: A Modular System for Automated Geologic Map Digitization"。USGS と作った地質図のデジタル化の仕組み。

- ジオリファレンスの出力を GCP (画素の位置と地上の位置の組) の集合と定義する。
- テキストの方法: 地図の領域の隅の座標注記を読む。表題の地名から、約 25 万枚の georeferenced な USGS 地形図の目録を引き、隅の点と目録の外接範囲を GCP の組にする。
- テキストで決まらないとき、候補の地形図と画像の特徴を比べる。
- 評価はジオリファレンスに 63 枚の地図。

取り入れること: GCP の集合を中間の成果物にする、隅の座標注記を最初に試す、既知の図郭の目録 (日本なら地形図の図郭や地域メッシュ) を使う。

## Plan2Map (arXiv:2606.02747)

Degen ほか (2026)、"Plan2Map: A Multimodal Benchmark for Document-Grounded Geospatial Boundary Reconstruction from Planning Records"。英国の計画文書の図から、計画地の境界ポリゴンを復元するベンチマーク。

- 道具を挟んで段階に分けた仕組み (証拠の抽出、位置の特定、地図の位置合わせ、境界の切り出し、投影) は、VLM に GeoJSON を直接出させる基準より大きく上回った (mean IoU 0.736、median IoU 0.904、IoU 0.8 以上が 67.8%)。
- 評価は IoU、重心の誤差 (m)、1 文書あたりの費用と時間。
- 段階ごとに、その段階の正解 (画素の IoU、座標) で別々に採点する診断を行っている。

取り入れること: 段階ごとの中間の成果物を正解と別々に照合できる形にする。最終の IoU だけで評価しない。

## Toponym-assisted map georeferencing (PLOS ONE 16(11): e0260039)

Bahgat と Runfola (2021)。地図の地名ラベルだけから、自動でジオリファレンスする方法と、その大規模な評価。再現用のコードは https://github.com/karimbahgat/ToponymGeoreferencingPaper (ライセンスは未確認)。

- 地名の曖昧さの解消: 画像の地名の点の配置と、地名辞典の候補の点の配置を、どちらも 0〜1 に正規化 (縦横比は保つ) して形を比べる。三つ組の一致を探し、組み合わせの数に上限を付ける。
- 変換: 1 次、2 次、3 次の多項式を比べる。選ぶ基準は GCP の残差の RMSE ではなく、leave-one-out の残差の最大値 (modelMaxLOO)。RMSE は過適合を隠し、高い次数を選びやすいため。
- 外れた GCP の除去: GCP を 1 つずつ外したときの modelMaxLOO を測り、最も良くなる点を外す。改善が閾値 (例: 10%) を下回るまで繰り返す。
- 評価: Natural Earth から描いた模擬の地図 7,580 枚で、真の変換が分かる状態で採点する。誤差は画素の誤差の最大値を画像の半径で割った割合。5% 未満を高精度とし、模擬の地図の 26.9% が 5% 未満、77.7% が 100% 未満だった。

取り入れること: 変換の選択と外れ値の除去を leave-one-out の最大残差で行う。真の変換が分かる模擬の地図を作って道具と関門を採点する。誤差を地図の大きさで正規化した指標と、地上の距離 (m) の指標を両方出す。
